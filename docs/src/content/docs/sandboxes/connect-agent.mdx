An agent uses a sandbox through the Arete MCP server (`a4 mcp`), which lists
the `sandbox_*` tools, or through `a4 sandbox` for reads. Both use the
agent's own account and a sandbox id.

## 1. Install and sign up

Paste into your agent:

<CopyPrompt>
Read https://docs.arete.run/agent.md and follow it to set up Arete in your
environment. Verify the setup, and simply explain what Arete is capable of.
</CopyPrompt>

That installs the signed `a4` binary, runs `a4 init -y` (skills, project
instructions and MCP configuration for the detected host), signs up a
restricted agent account and runs `a4 doctor`. To do it by hand:

```bash
curl -fsSL https://arete.run/install.sh | sh     # Windows: irm https://arete.run/install.ps1 | iex
a4 init -y
a4 --profile agent auth signup --if-missing --json
a4 doctor --summary --json
```

## 2. Give it the sandbox

[Grant the agent's account](/sandboxes/agents/#grants) on the sandbox's page,
then set `ARETE_SANDBOX_ID` for the MCP server. In the host's MCP
configuration, add it to the `arete` server's `env`:

```json
{
  "mcpServers": {
    "arete": {
      "command": "a4",
      "args": ["--profile", "agent", "mcp"],
      "env": { "ARETE_SANDBOX_ID": "<sandbox id>" }
    }
  }
}
```

Restart the host so it starts the server again. Where each host keeps its
configuration (Claude Code, Cursor, VS Code, Codex, OpenCode, Gemini CLI) is
in the [MCP reference](/agent-skills/mcp/#configure-your-agent-1).

Running the server by hand works the same way:

```bash
export ARETE_SANDBOX_ID=<sandbox id>
a4 --profile agent mcp
```

`ARETE_API_KEY` set to the agent account's secret key replaces the stored
login, for hosts without one.

## 3. Check it

Ask the agent:

<CopyPrompt>
Call sandbox_status and sandbox_rules, and tell me the wallet's balance, the
actions you are granted and the programs you may use.
</CopyPrompt>

If the tools are missing, `ARETE_SANDBOX_ID` isn't reaching the server. If
they fail with `sandbox-grant-missing`, the grant isn't in place yet.

## MCP tools

| Tool               | What it does                                                                            |
| ------------------ | --------------------------------------------------------------------------------------- |
| `sandbox_status`   | The wallet, its balances and the actions this agent may run. Start here.                |
| `sandbox_rules`    | The allowed programs, instructions with their arguments and accounts, limits, allowlist |
| `sandbox_derive`   | An address: a PDA (computed locally) or an associated token account                     |
| `sandbox_preview`  | A dry run: `pass` and what the wallet would lose, or the refusal                        |
| `sandbox_invoke`   | Runs one action: the only tool that moves funds                                         |
| `sandbox_action`   | One action's status, by id or idempotency key                                           |
| `sandbox_history`  | Read-only: past actions, newest first, decoded                                          |
| `sandbox_holdings` | Read-only: SOL, tokens and program positions                                            |

Arguments for each are in the [MCP reference](/agent-skills/mcp/#sandbox-tools).
Where your account has them, the server also lists read tools (`read_view`,
`explore_*`, `search_catalog`) for the [read side](/sandboxes/read-scope/).

## CLI

| Command                            | What it does                        |
| ---------------------------------- | ----------------------------------- |
| `a4 sandbox history`               | The sandbox's actions, newest first |
| `a4 sandbox holdings`              | What it holds now                   |
| `a4 sandbox rules show`            | The rules, as the agent sees them   |
| `a4 sandbox rules validate <file>` | Check a Rules v3 file locally       |

Each takes `--sandbox <id>` (default `ARETE_SANDBOX_ID`) and `--json`. The
CLI never runs an action: actions go through `sandbox_invoke`. See the
[CLI reference](/cli/commands/#a4-sandbox).

## Prompts

<CopyPrompt>
What does my sandbox hold, and what changed in the last 24 hours? Use
sandbox_holdings and sandbox_history, and cite signatures.
</CopyPrompt>

<CopyPrompt>
Which programs and instructions do my sandbox's rules allow, and how much of
each spend limit is left?
</CopyPrompt>

<CopyPrompt>
Your last sandbox action was refused. Explain the refusal from its code, rule
and hint, and tell me whether you can fix it or I need to change the rules.
</CopyPrompt>

<CopyPrompt>
Sell everything the sandbox bought back to SOL. Preview each sale first and
show me the totals before running them.
</CopyPrompt>

## Good instructions for a sandboxed agent

The [sandbox skill](/sandboxes/skill/) teaches this already. For hosts
without skills, put guidance like this in the agent's instructions:

- Read `sandbox_status` and `sandbox_rules` before acting; use only programs
  and instructions they list.
- Preview every action with `sandbox_preview` before `sandbox_invoke`.
- Pass amounts as decimal strings in the smallest unit.
- On a refusal, follow its `hint`. With `retryable: false`, change the request
  before trying again.
- After a timeout on `sandbox_invoke`, look the action up with
  `sandbox_action` and its `idempotencyKey` before retrying.
