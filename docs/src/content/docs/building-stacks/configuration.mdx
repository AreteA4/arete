title: Project Dependencies
description: Use arete.toml, arete.lock, and generated provenance to manage programs and stacks.
---

An Arete project has three related dependency records:

- `arete.toml` — human-authored intent;
- `arete.lock` — exact immutable resolution; and
- generated SDK provenance — which locked input produced each output.

Use `a4 install`, `a4 update`, and `a4 remove` to keep all three consistent.

## Initialize

```bash
a4 init -y
```

Initialization creates a minimal manifest if one does not exist and configures
the project's agents. It does not invent registry dependencies.

```toml
manifest_version = 1

[project]
name = "my-project"
private = true
```

## Add dependencies through the CLI

Start with the catalog, inspect the exact descriptor, and prefer its install
command:

```bash
a4 explore catalog --query "token accounts" --json
a4 explore catalog program spl-token --json
a4 install program spl-token --ts
```

For a hosted stack:

```bash
a4 explore catalog --query "<intent>" --kind stack --mode subscribe --json
a4 explore catalog stack <slug> --json
a4 install stack <slug> --ts
```

The add command saves dependency intent and resolves the complete graph. Run
plain `a4 install` later to restore every declared dependency.

## Manifest structure

```toml
manifest_version = 1

[project]
name = "my-analytics-app"
private = true

[install]
allow_outside_project = false

[sdk]
targets = ["typescript", "rust"]

[sdk.typescript]
output_dir = "./src/generated"
package = "@my-org/arete-generated"

[sdk.rust]
output_dir = "./crates/generated"
module_mode = true
crate_prefix = "my_app"

[sdk.python]
output_dir = "./python/generated"
module_mode = false
package_prefix = "my_app"

[dependencies.programs.token]
source = { registry = "spl-token" }
version = "^1.0.0" # use the requirement saved by the current install command
targets = ["typescript"]

[dependencies.programs.token.outputs]
typescript = "./src/generated/programs/token"

# Illustrative: replace with a stack slug and version returned by its descriptor.
[dependencies.stacks.market-data]
source = { registry = "market-data" }
version = "^1.0.0"
targets = ["typescript", "rust"]
```

Do not copy illustrative package names or versions without checking the
catalog. `a4 install` writes the correct table from the selected descriptor.

## Sources

A dependency has exactly one source:

| Source      | Meaning                                                      |
| ----------- | ------------------------------------------------------------ |
| `registry`  | Resolve a published package by slug and version requirement  |
| `path`      | Use an exact local `ProgramSpec` or `StackManifest` artifact |
| `workspace` | Refer to a same-kind entry under `[authoring]`               |

Registry requirements are human intent. The lockfile records the exact package
release and artifact identities that satisfied them.

Registry versions use
[Arete's semantic versioning system](/concepts/program-versioning/). They
describe compatibility of the published Arete package.

## Output layout

Without dependency-specific overrides, outputs are namespaced by kind:

- TypeScript: `<output_dir>/stacks/<alias>` and
  `<output_dir>/programs/<alias>`;
- Rust: `<output_dir>/stacks/<prefix>-<alias>-stack` and
  `<output_dir>/programs/<prefix>-<alias>-program`;
- Python: `<output_dir>/stacks/<prefix>-<alias>-stack` and
  `<output_dir>/programs/<prefix>-<alias>-program`.

This permits a stack and standalone program to share an alias. Aliases must be
unique within their own kind.

A dependency-level output is an exact override and does not receive the
automatic kind directory.

## Install and update

```bash
a4 install
a4 install --locked
a4 install --dry-run
a4 update
a4 update program token
a4 remove program token
```

Important behaviors:

- `a4 install` resolves the complete declared graph.
- `--locked` requires a fresh existing lock and never changes resolution.
- `--dry-run` validates and prints the plan without writing.
- a package add saves intent unless `--no-save` is explicit.
- generated output and `arete.lock` are committed only after successful
  generation of the complete graph.
- `a4 update` changes resolution; plain install does not silently replace an
  exact fresh lock.

Generated directories are owned outputs. Do not hand-edit entry files,
extensions, SDK manifests, or provenance records.

## Lockfile

Commit `arete.lock` for applications and services that need reproducible
generation. It pins exact package and artifact identities, not only semantic
versions.

After merging dependency changes, CI should run:

```bash
a4 install --locked
```

A stale lock is a project health warning reported by `a4 doctor`.

## Local authoring

Authored artifacts have stable project names under `[authoring]`:

```toml
[authoring.stacks.local-indexer]
manifest = "./.arete/LocalIndexer.stack-manifest.json"
artifact_roots = ["./.arete"]
deployment_name = "local-indexer"

[dependencies.stacks.indexer]
source = { workspace = "local-indexer" }
```

`artifact_roots` grants explicit access to the related content-addressed files.
Workspace dependencies make local authored content part of normal project SDK
generation.

The lower-level `a4 sdk create` command is useful for direct artifact work. It
does not write `arete.toml` or `arete.lock` and should not replace dependency-
backed installation for application projects.

## Validate

```bash
a4 config validate
a4 doctor --json
```

Validation is offline. It checks strict keys, source and workspace kinds, local
artifact closure, path policy, output collisions, and lock freshness. It does
not prove that a hosted binding is healthy; inspect the exact descriptor and
perform a bounded read when that matters.

## Credentials and environment

Authentication is stored separately from the project manifest. Use:

```bash
a4 auth signup
a4 auth login --key <a4_ak_...>
```

Never commit credentials. In headless environments, configure the supported
secret environment through the CI secret manager.

| Variable        | Purpose                         |
| --------------- | ------------------------------- |
| `ARETE_API_URL` | Intentional API origin override |
| `ARETE_API_KEY` | Headless authentication         |

An API override changes the trust boundary. Do not send a production key to an
untrusted origin.
