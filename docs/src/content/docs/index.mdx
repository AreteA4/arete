# From an on-chain question to a typed Solana application

Arete is an **agent-first Solana application toolkit**. Your agent can discover
programs from your intent, inspect and query deployed live views, and install
the result as a fully typed SDK for reads, transactions, flows, and real-time
data.

You can start by asking a question. You do not need to know the program ID,
account layout, view name, or endpoint first.

1. **Explore** — the agent searches the catalog by intent, identifies suitable
   programs and views, and uses MCP to inspect current or live state.
2. **Shape** — reuse an existing view, or define a focused read model when the
   catalog does not contain what the application needs.
3. **Ship** — record the selected programs and stacks in `arete.toml`, lock
   their exact identities, generate the SDK, and build against stable types.

## Start with one prompt

Open your project in a coding agent and paste this:

<CopyPrompt>
Read https://docs.arete.run/agent.md and follow it to set up Arete in this
project. Verify the setup, and simply explain what Arete is capable of.
</CopyPrompt>

That one URL gives the agent the supported CLI installer, project initialization
command, health check, catalog workflow, and task routing. `a4 init` installs the
skills and configures both MCP servers for the detected agent.

[See the manual equivalent →](/using-stacks/quickstart/)

## Programs are the foundation

Arete turns each supported Solana program into a generated Program SDK. The
exact surface depends on the program and selected SDK target, but follows one
model:

| Surface | What it gives you |
| --- | --- |
| **Accounts** | Release-pinned, typed account reads |
| **PDAs and addresses** | Deterministic derivation without copied seed logic |
| **Raw instructions** | Pure builders matching the normalized program schema |
| **Operations and flows** | Application-shaped preparation, including multi-instruction and multi-transaction work |
| **Transactions** | Local signing, inspection, submission, confirmation, and safe failure outcomes |
| **Chain** | Generic Solana reads for data outside a program account surface |

[Understand Program SDKs →](/using-programs/overview/)

## Add live views where they help

Program accounts are the base data. **Live views** are optional application
read models over one or more programs: current positions, active rounds,
rankings, aggregates, filtered activity, or any other state that is useful to
read together.

A **stack** packages selected live views with the Program SDKs they depend on.
Applications install stacks; they do not need to know how views are grouped or
hosted internally.

[Programs, views, and stacks →](/concepts/programs-views-stacks/)

## Exact, inspectable dependencies

`arete.toml` records what the project intends to use. `arete.lock` records the
exact program, stack, artifact, and generated-package identities selected by
`a4 install`. Generated outputs include provenance and should be regenerated,
not edited by hand.
