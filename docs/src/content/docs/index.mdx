# Sandboxes for AI agents on Solana

An Arete **sandbox** is a financial virtual machine for your agent: a funded
Solana wallet the agent can trade and act from, inside rules you sign. The
agent asks for an action; Arete builds the transaction, checks it against your
rules, signs it and sends it. The agent never sees a private key, a
transaction to sign or an RPC URL.

:::caution[Alpha]
Sandboxes are in public alpha and hold real funds. Fund a sandbox only with
what you are prepared to lose.
:::

## Start with one prompt

Open your agent and paste:

<CopyPrompt>
Read https://docs.arete.run/agent.md and follow it to set up Arete in your
environment. Verify the setup, and simply explain what Arete is capable of.
</CopyPrompt>

The agent installs the `a4` CLI and the Arete MCP server. Then
[create a sandbox](/sandboxes/quickstart/), grant the agent access and give it
the sandbox id.

## Why a sandbox

<CardGrid>
  <Card title="No key handover" icon="seti:lock">
    The wallet's key never leaves Arete. The agent names actions; Arete signs
    them, and only when they pass your rules.
  </Card>
  <Card title="Write scope" icon="approve-check">
    Only the programs and instructions you enabled, within per-program spend
    limits. Funds can leave only to your wallet, addresses you allowed, or the
    sandbox's own accounts.
  </Card>
  <Card title="Read scope" icon="magnifier">
    The same rules decide what the agent can see. Program reads and live views
    are the sandbox's read side: a program that isn't in the sandbox is one
    the agent can't call and can't read.
  </Card>
  <Card title="Auditable and revocable" icon="list-format">
    Every action is recorded, refusals included, with decoded instructions,
    events and balance changes. Revoke a grant and the agent stops at its next
    call.
  </Card>
  <Card title="Refusals an agent can act on" icon="information">
    Each refusal names its `code`, the `rule` that refused, whether to retry
    and what to change, so the agent corrects the request instead of guessing.
  </Card>
  <Card title="Exits always allowed" icon="right-arrow">
    The agent may always sell or exit a token the sandbox bought, so a
    position is never stuck behind a rule.
  </Card>
</CardGrid>

Read scoping is rolling out; see [Read scope](/sandboxes/read-scope/) for what
applies today.
