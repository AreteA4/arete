# Build a protocol. Run it. Put it in your app.

Arete lets you compose Solana programs into a protocol with defined steps,
permissions, and lifecycle. Write the definition in TypeScript, try it against
a persistent mainnet fork, and use the generated client from an app or agent.
Wallets sign locally; the underlying Solana programs execute the transactions.

## Define what your product does

A raise has contributors, a deadline, and different outcomes. A deal has
counterparties and a settlement step. These are more than individual
transactions: they have instances, participants, permissions, and state.

An **Arete Protocol** describes that workflow. Its steps compose instructions
from installed programs, check guards, and declare who signs. Its lifecycle
can respond to confirmed activity, chain state, and time. Generated clients
expose those steps and their typed arguments, current state, and events.

[Understand protocols →](/getting-started/what-is-arete/)

## Develop against real programs

`a4 dev up` runs your protocol in a cloud dev environment: a persistent fork
of mainnet hosted for your account. Fund test wallets, advance time, inspect
activity, save checkpoints, and replay steps. Your local app and coding agent
use the protocol API against that environment while you edit.

There is no local validator to install. The CLI, dev UI, and wallet keys stay
on your machine. Dev-environment SOL has no mainnet value.

[Develop and test →](/cli/local-development/)

## Connect an app or agent

Install a protocol to get its generated client, including the stacks and
programs it depends on. An app can discover what a wallet can do, prepare a
step, ask the wallet to sign, submit it, and follow the outcome. React hooks
follow instances, participants, and available actions. MCP gives agents the
same protocol workflow.

## Extend with programs and live data

Program SDKs provide account readers, address helpers, and instruction builders.
Live views arrange chain data for your application; stacks bundle those views
with their programs. Use them within a protocol or independently when your
application only needs reads, transactions, or subscriptions.
