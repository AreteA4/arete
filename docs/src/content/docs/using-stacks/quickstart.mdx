This quickstart prepares a project for both agent-led exploration and generated
SDK development. It does not depend on a hard-coded hosted stack.

## Fastest path: give your agent one URL

Open the project in your coding agent and paste:

<CopyPrompt>
Read https://docs.arete.run/agent.md and follow it to set up Arete in this
project. Verify the setup, then find programs and live views that can help me
understand recent token activity. Inspect exact descriptors, query a bounded
live sample when available, and summarize what the data supports. If no suitable
hosted view exists, show me the closest program capabilities instead of guessing.
</CopyPrompt>

The agent installs the CLI, runs `a4 init -y`, checks the environment with
`a4 doctor --json`, and tells you if the host must be reloaded to pick up its
new skills or MCP configuration. The steps below are the manual equivalent and
a reference for what the agent does.

Replace “understand recent token activity” with your own question or feature.

## 1. Install the CLI

<Tabs syncKey="installer">
<TabItem label="macOS / Linux">

```bash

```

</TabItem>
<TabItem label="Windows PowerShell">

```powershell

```

</TabItem>
<TabItem label="npm">

```bash
npx @usearete/a4 install
```

</TabItem>

The installer downloads the signed prebuilt binary and prints its absolute
path. No Rust toolchain is required. Update it later with `a4 self update`.

:::note[Two different installs]
`npx @usearete/a4 install` installs the **CLI**. Once `a4` is available,
`a4 install` resolves and generates the **project's Arete dependencies**.
:::

## 2. Initialize the project

Run this from the project root:

```bash
a4 init -y
a4 doctor --json
```

`a4 init` is idempotent. It configures the project for agents by writing or
updating:

- `arete.toml`;
- the managed Arete instructions in `AGENTS.md`;
- the bridge used by agents that read `CLAUDE.md`;
- the five Arete skills; and
- the Arete stream and documentation MCP servers.

`a4 doctor --json` checks the CLI, project manifest, lockfile, skills, and MCP
configuration. Follow the reported `fix` command for any required failure.

There is no `a4 knit` command; `a4 init` is the project setup command.

## 3. Explore by intent

Ask the catalog for a capability rather than guessing a package:

```bash
a4 explore catalog --query "token account balances" --json
a4 explore catalog --kind program --mode read --target typescript --json
```

Inspect one exact result:

```bash
a4 explore catalog program spl-token --json
```

The response reports the exact program identity, available modes, account and
instruction surface, Program Read status, verified SDK targets, and install
command. Catalog contents change independently of these docs, so current CLI
output is the authority.

## 4. Install the Program SDK

```bash
a4 install program spl-token --ts
```

The command:

1. adds the dependency to `arete.toml`;
2. resolves exact package and artifact identities;
3. writes `arete.lock`; and
4. generates the TypeScript SDK at the configured output location.

Read the command's output for the exact import path. Generated files are owned
by the installer; update the dependency or source and regenerate instead of
editing them.

To reproduce the project later:

```bash
a4 install --locked
```

Use `--rust` or `--python` only if the exact descriptor verifies that target.

## 6. Ask an on-chain question through MCP

The project is also ready for interactive exploration:

<CopyPrompt>
Use Arete to find any currently deployed live views relevant to token activity.
Inspect their exact schemas, connect to the most useful view, gather a bounded
sample, summarize what the data supports, and disconnect. If there is no
suitable subscribe-ready view, say so and show me the nearest read-ready
programs instead.
</CopyPrompt>

Hosted knowledge and live connections may require an account:

```bash
a4 auth signup
```

The agent should use catalog results dynamically. It should not rely on an ORE
deployment or any other named stack being public forever.

## What is ready now?

Arete distinguishes knowledge from delivery. A result may be cataloged while
only some modes are ready:

| Mode        | Use it for                               |
| ----------- | ---------------------------------------- |
| `read`      | Program accounts and generic chain state |
| `build`     | Instructions, transactions, and flows    |
| `subscribe` | Hosted point-in-time and live views      |

Always search for the mode you need and inspect the exact descriptor before
writing application code.
