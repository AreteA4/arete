The `arete-a4-sdk` crate is the Rust client for generated Program SDKs and
stacks. It mirrors the core TypeScript model with native Rust idioms: generated
structs, builder chains, and `Stream` implementations.

## Install the runtime

```toml
[dependencies]
arete-sdk = { package = "arete-a4-sdk", version = "{{VERSION}}" }
tokio = { version = "1", features = ["rt-multi-thread", "macros"] }
futures = "0.3"
anyhow = "1"
```

The default TLS backend is `rustls`. To use native TLS:

```toml
arete-sdk = { package = "arete-a4-sdk", version = "{{VERSION}}", default-features = false, features = ["native-tls"] }
```

## Generate the application package

Find a Rust-ready program or stack and install it into the project:

```bash
a4 explore catalog --query "<intent>" --target rust --json
a4 explore catalog stack <slug> --json
a4 install stack <slug> --rust
```

Use `a4 install program <slug> --rust` for a standalone Program SDK. Read the
CLI output for the generated crate name and path; those depend on the project
configuration and dependency alias.

## Connect to a generated stack

```rust
use arete_sdk::prelude::*;
use my_stack::MyStack;

#[tokio::main]
async fn main() -> anyhow::Result<()> {
    let client = Arete::<MyStack>::builder()
        .publishable_key(std::env::var("ARETE_PUBLISHABLE_KEY")?)
        .connect()
        .await?;

    let positions = client.views.position.list().get().await;
    println!("{positions:?}");

    client.disconnect().await;
    Ok(())
}
```

`MyStack`, `position`, and the generated crate path are placeholders. Use the
types and view accessors emitted for the installed package.

## Live views

Every generated entity has its declared keyed and collection views. Derived
views can add package-specific filters, sorting, and bounded windows.

### Merged entities

`listen()` yields current entity values with patches applied and removals
filtered out:

```rust
let mut positions = client.views.position.list()
    .listen()
    .take(10);

while let Some(position) = positions.next().await {
    println!("{position:?}");
}
```

### Full update taxonomy

Use `watch()` when the application must distinguish a row changing, leaving
one query, or being deleted globally:

```rust
let mut updates = client.views.position.list()
    .watch()
    .filter("state.status", "open")
    .take(20)
    .with_snapshot_limit(100);

while let Some(update) = updates.next().await {
    match update {
        Update::Upsert { key, data } => println!("upserted {key}: {data:?}"),
        Update::Patch { key, data } => println!("patched {key}: {data:?}"),
        Update::Remove { key } => println!("{key} left this query"),
        Update::Delete { key } => println!("{key} was deleted globally"),
    }
}
```

Use `watch_rich()` when the generated view supports before/after diffs.

Subscriptions are lazy and reference-counted. Equivalent normalized queries
share a wire subscription and unsubscribe when the final stream is dropped.

## Program SDK

Generated program modules expose pure instruction builders and PDA helpers.
The output is an Arete `BuiltInstruction`; no wallet or network is required:

```rust
use my_program::{self, DepositParams};

let instruction = my_program::deposit(DepositParams {
    owner: owner.clone(),
    amount: 1_000_000,
    ..Default::default()
})?;

let (position, bump) = my_program::pdas::position(&owner)?;
```

Connected stack clients expose the same generated program under
`client.programs`. Exact method and parameter names come from the generated
crate.

PDA derivation fills supported literal, argument, and account-reference seeds.
Unknown parameters and missing required values fail closed.

## Program Read

Generated program clients expose account readers tied to the exact installed
release:

```rust
let position = client
    .programs
    .my_program
    .position_accounts()?
    .fetch(&position_address)
    .await?;
```

Use the generated reader method rather than the placeholder above. Program
Read is independent of the live view endpoint.

## Generic chain reads

```rust
let clock = client.chain().clock().await?;
let balance = client
    .chain()
    .native_balance(&address, Default::default())
    .await?;
```

Use the chain surface for generic Solana state and the generated program reader
for typed program accounts.

## Transactions

The core SDK builds portable instructions but does not choose a Solana signing
implementation. Attach a wallet adapter, then execute instructions or prepared
operations:

```rust
let client = Arete::<MyStack>::builder()
    .publishable_key(publishable_key)
    .wallet(wallet)
    .connect()
    .await?;

let receipt = client
    .transaction(&[instruction], TransactionOptions::default())
    .await?;

let receipt = client
    .execute(&prepared, ExecuteOptions::default())
    .await?;
```

The wallet compiles and signs locally. Execution classifies outcomes as
confirmed, definitely not submitted, submitted with unknown outcome, or failed
on chain. Do not automatically resend a `submitted-unknown` transaction.

### Optional Solana adapter

Enable the first-party adapter only when the application wants the SDK to build
legacy, v0, or transaction-V1 messages:

```toml
arete-sdk = { package = "arete-a4-sdk", version = "{{VERSION}}", features = ["solana-adapter"] }
```

The adapter submits a signed transaction at most once. One deadline covers
submission and confirmation. Direct RPC is an explicit transport selection;
there is no silent hosted-to-direct fallback after an operation begins.

## Sessions

Use a session when an application composes several generated stacks:

```rust
let session = Session::builder()
    .stack::<MarketsStack>("markets")
    .stack::<PositionsStack>("positions")
    .wallet(wallet)
    .connect()
    .await?;

let positions = session.stack::<PositionsStack>("positions")?;
session.execute(&prepared, Default::default()).await?;
session.close().await;
```

Sessions share wallet and execution configuration while keeping each stack's
exact programs, views, and hosted bindings explicit.

## HTTP-only mode

HTTP-only transport keeps Program Read, chain reads, point-in-time stack
queries, and transaction execution available. Live view subscriptions fail
fast because they require WebSocket transport.

## Connection lifecycle

```rust
client.connection_state().await;
let mut issues = client.subscribe_socket_issues();
client.disconnect().await;
```

Reconnects replay active subscriptions and apply an authoritative snapshot to
replace local state. Preserve socket and schema-validation diagnostics in
application logs.
