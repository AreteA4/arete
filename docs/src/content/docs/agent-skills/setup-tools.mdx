Arete works with coding agents that can run commands and use MCP tools. You can
use Cursor, Claude Code, Codex, OpenCode, VS Code agents, or another supported
client. The Arete workflow does not depend on one editor.

## 1. Open a project folder

Create or open the directory where you want the agent to work. Project-scoped
setup is recommended because dependencies, instructions, skills, and MCP
configuration can be reviewed with the rest of the project.

```bash
mkdir my-arete-project
cd my-arete-project
git init
```

## 2. Give the agent the bootstrap page

Paste this prompt into the agent:

<CopyPrompt>
Read https://docs.arete.run/agent.md and follow it to set up Arete in this
project. Verify the setup, and simply explain what Arete is capable of.
</CopyPrompt>

The agent should:

1. install the signed `a4` CLI binary;
2. run `a4 init -y`;
3. run `a4 doctor --json`; and
4. follow exact repair commands for required failures.

No Rust toolchain or Arete account is required for basic setup and public
catalog discovery.

## 3. Reload the agent

`a4 init` writes MCP configuration for detected agents. Terminal agents often
pick this up immediately; GUI applications may need a full restart so they
reload configuration and the updated PATH.

Ask the agent to confirm that it can see:

- the `arete` MCP server for discovery and live views; and
- the `arete-docs` MCP server for documentation search.

If either is missing:

```bash
a4 doctor --json
a4 doctor --fix
```

Review the reported changes and restart the agent again.

## 4. Ask an on-chain question

<CopyPrompt>
Use Arete to find programs and currently deployed views related to [YOUR
QUESTION]. Inspect exact descriptors, gather only a bounded live sample,
explain which programs and views support the answer, and disconnect when
finished. If no suitable hosted view exists, tell me which program capabilities
are closest instead of guessing.
</CopyPrompt>

Knowledge lookup and hosted connections may require authentication. When the
agent reports that requirement, run:

```bash
a4 auth signup
```

or log in with a key you already control:

```bash
a4 auth login --key <a4_ak_...>
```

Do not paste credentials into chat or source code.

## 5. Turn the result into code

Once exploration identifies the correct capability, ask the agent to install
it and build against the generated types:

<CopyPrompt>
Install the exact Arete program or stack we just validated into this project
for [LANGUAGE]. Preserve arete.toml and arete.lock, inspect the generated SDK,
and implement [FEATURE] using generated names and types. Do not edit generated
files or reuse MCP cache data as an application dependency.
</CopyPrompt>

The agent should use `a4 install program ...` for standalone program reads and
transactions, or `a4 install stack ...` when the application needs the selected
live views.

## What the setup writes

Depending on the detected agent, `a4 init` may create or update:

- `arete.toml`;
- an Arete-managed block in `AGENTS.md`;
- a `CLAUDE.md` bridge;
- `.agents/skills` or an agent-specific skill directory;
- project MCP configuration; and
- `skills-lock.json`.

Re-running `a4 init` updates managed sections without replacing unrelated
project instructions.

## Safety expectations

An agent can search, read, generate local code, and inspect transactions without
transaction or deployment authority. Signing, submitting, publishing, and
deploying are separate actions and require an explicit request.
