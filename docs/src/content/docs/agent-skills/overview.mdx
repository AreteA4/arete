Arete is designed so an agent can move from a product question to exact,
generated application code without guessing program schemas or infrastructure.

## Start with one URL

Open the project in your coding agent and paste:

<CopyPrompt>
Read https://docs.arete.run/agent.md and follow it to set up Arete in this
project. Verify the result, tell me if the agent needs to be restarted, then ask
me what on-chain question or program I want to explore.
</CopyPrompt>

The bootstrap page leads the agent through CLI installation, `a4 init`, and
`a4 doctor`. The installed skills and current CLI output take over from there.

## The agent workflow

```text
Understand intent
  → search the catalog
  → inspect exact descriptors
  → explore live views through MCP
  → install programs and stacks
  → build against generated types
```

The human provides goals and authority. The agent handles discovery, exact
schema lookup, dependency generation, and repetitive integration work.

## Manual setup

```bash
curl -fsSL https://arete.run/install.sh | sh
a4 init -y
a4 doctor --json
```

`a4 init` detects supported coding agents and configures:

- `arete.toml` for project dependencies;
- managed Arete instructions in `AGENTS.md`;
- the five Arete skills;
- the local `arete` MCP server; and
- the remote `arete-docs` MCP server.

It is safe to run again. Use `a4 doctor --fix` when doctor reports repairable
configuration drift.

## The five skills

| Skill                   | When the agent uses it                                                               |
| ----------------------- | ------------------------------------------------------------------------------------ |
| `arete`                 | Setup, capability discovery, exact descriptors, and project dependencies             |
| `arete-streams`         | Live views, point-in-time view reads, filtering, subscriptions, and stream debugging |
| `arete-programs`        | Program accounts, PDAs, instruction building, operations, transactions, and safety   |
| `arete-stack-authoring` | Designing custom application read models and compiling portable artifacts            |
| `arete-deploy`          | Publication and permission-aware hosted deployment operations                        |

Skills contain workflow guidance. They do not freeze program schemas. The
agent must still inspect the current descriptor and generated code.

## MCP for exploration

The `arete` MCP server lets an agent search known capabilities, inspect view
schemas, connect to hosted stacks, subscribe, and query a bounded local cache.
This makes a natural-language question a useful first interaction with Arete.

<CopyPrompt>
Find Arete programs and hosted views that can answer my question about recent
liquidity changes. Inspect the exact view schemas, collect a bounded live
sample, explain the result and its limitations, and disconnect. Do not guess
program names, view names, or endpoints.
</CopyPrompt>

## Generated SDKs for shipped code

MCP is an exploratory client, not the production application API. Once a
program or view is part of the product, the agent adds the dependency and uses
generated types:

```bash
a4 install program <slug> --ts
a4 install stack <slug> --ts
```

`arete.toml` records intent and `arete.lock` pins exact content. The generated
surface, descriptor, and current CLI output take precedence over prose examples.

## Sources of truth

Agents should resolve conflicts in this order:

1. Generated types and exact installed descriptors
2. Current `a4 <command> --help` and machine-readable JSON
3. Current Arete documentation
4. General skill guidance

This prevents copied prompts or old examples from overriding the capability
actually installed in the project.

## Authority boundaries

Agent-first does not mean authority-free:

- discovery, reads, local generation, and transaction inspection are read-only;
- preparing a transaction does not authorize signing;
- signing or submitting requires the user's intended wallet action;
- an ambiguous submission must not be blindly retried; and
- compiling an artifact does not authorize publishing or deploying it.

The deployment skill preserves the same distinction between planning,
submission, and a resource reaching its ready state.

For manual configuration and exact tool contracts, see [MCP Servers](/agent-skills/mcp/).
