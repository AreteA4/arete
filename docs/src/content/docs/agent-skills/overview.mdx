Arete is built so that an agent can take you from a product question to exact,
generated application code, without guessing at program schemas or
infrastructure along the way. This page explains who does what.

## Start with one URL

Open the project in your coding agent and paste:

<CopyPrompt>
Read https://docs.arete.run/agent.md and follow it to set up Arete in this
project. Verify the setup, and simply explain what Arete is capable of.
</CopyPrompt>

That bootstrap page walks the agent through installing the CLI, running
`a4 init`, and running `a4 doctor`, then asks it to summarize what Arete can do.
You don't need an on-chain question ready just to finish setup. Bring one when
you're ready to explore. From that point on, the installed skills and the
CLI's current output guide the agent.

## The agent workflow

```text
Understand intent
  → search the catalog
  → inspect exact descriptors
  → explore live views through MCP
  → install programs and stacks
  → build against generated types
```

You bring the goals and the authority to approve things. The agent handles
discovery, exact schema lookup, dependency generation, and the repetitive
integration work.

## Manual setup

Prefer to run the setup yourself? It is three commands:

```bash
curl -fsSL https://arete.run/install.sh | sh
a4 init -y
a4 doctor --json
```

`a4 init` detects the coding agents you have and configures:

- `arete.toml` for project dependencies;
- managed Arete instructions in `AGENTS.md`;
- the five Arete skills;
- the local `arete` MCP server; and
- the remote `arete-docs` MCP server.

It is safe to run again. If doctor reports configuration that has drifted and
can be repaired, run `a4 doctor --fix`.

## The five skills

A skill is a set of instructions your agent loads when a task calls for it.
Arete installs five:

| Skill                   | When the agent uses it                                                               |
| ----------------------- | ------------------------------------------------------------------------------------ |
| `arete`                 | Setup, capability discovery, exact descriptors, and project dependencies             |
| `arete-streams`         | Live views, point-in-time view reads, filtering, subscriptions, and stream debugging |
| `arete-programs`        | Program accounts, PDAs, instruction building, operations, transactions, and safety   |
| `arete-stack-authoring` | Designing custom application read models and compiling portable artifacts            |
| `arete-deploy`          | Publication and permission-aware hosted deployment operations                        |

Skills teach the agent how to work. They don't hard-code any program's schema,
so the agent still has to inspect the current descriptor and the generated
code.

## MCP for exploration

The `arete` MCP server lets an agent search what Arete knows, inspect view
schemas, connect to hosted stacks, subscribe, and query a bounded local cache.
This is why a plain-language question works so well as your first interaction
with Arete.

<CopyPrompt>
Find Arete programs and hosted views that can answer my question about recent
liquidity changes. Inspect the exact view schemas, collect a bounded live
sample, explain the result and its limitations, and disconnect. Do not guess
program names, view names, or endpoints.
</CopyPrompt>

[Explore on-chain with MCP →](/agent-skills/explore-on-chain/)

## Generated SDKs for shipped code

MCP is for exploring. It is not the API your production application should
call. Once a program or view becomes part of the product, the agent adds it as a
dependency and works from generated types:

```bash
a4 install program <slug> --ts
a4 install stack <slug> --ts
```

`arete.toml` records what you asked for, and `arete.lock` pins the exact
content. When prose examples disagree with the generated code, the descriptor,
or current CLI output, the examples lose.

## Sources of truth

When sources conflict, agents should trust them in this order:

1. Generated types and exact installed descriptors
2. Current `a4 <command> --help` and machine-readable JSON
3. Current Arete documentation
4. General skill guidance

This stops a copied prompt or an old example from overriding what is really
installed in the project.

## Authority boundaries

Agent-first does not mean the agent can do anything it likes:

- discovery, reads, local generation, and transaction inspection are read-only;
- preparing a transaction does not authorize signing it;
- signing or submitting requires a wallet action you intended;
- a submission whose outcome is unclear must not be blindly retried; and
- compiling an artifact does not authorize publishing or deploying it.

The deployment skill draws the same lines between planning a deployment,
submitting it, and a resource reaching its ready state.

For manual configuration and exact tool contracts, see [MCP Servers](/agent-skills/mcp/).
