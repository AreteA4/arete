---
title: Catalog and Descriptors
description: Search the catalog by what you want to do, then open the exact spec sheet for a program or stack.
---

Finding something in Arete happens in two steps. First you **search**, to see
what might fit. Then you **inspect** one exact result, to see what it really
offers. Your agent normally does both for you. This page shows the commands
behind each step, which is handy when you want to check the agent's work or
script it yourself.

Three things are involved:

- the **catalog** helps an agent find programs and stacks that match what you
  want to do;
- a **descriptor** is the exact spec sheet for one installable package,
  including how it can be delivered; and
- **generated code** supplies the final names and types in your language.

## Search the catalog

Describe the job in your own words with `--query`, then narrow the results
with filters:

```bash
a4 explore catalog --query "monitor swaps" --json
a4 explore catalog --query "manage a multisig" --kind program --json
a4 explore catalog --category defi --mode subscribe --json
a4 explore catalog --kind program --mode read --target typescript --json
```

Available filters:

| Filter                | Meaning                                               |
| --------------------- | ----------------------------------------------------- |
| `--query`             | Free-text intent                                      |
| `--concept`           | Exact catalog concept slug                            |
| `--category`          | Exact category slug                                   |
| `--kind`              | `program` or `stack`                                  |
| `--mode`              | `read`, `build`, or `subscribe`                       |
| `--target`            | Verified `typescript`, `rust`, or `python` SDK output |
| `--limit`, `--cursor` | Bounded pagination                                    |

List canonical concept and category slugs before using exact filters:

```bash
a4 explore catalog --vocabulary --json
```

The catalog is live and keeps changing. Don't keep a hand-written “available
stacks” list in your application instructions, because it will go stale.

## Inspect an exact result

```bash
a4 explore catalog program <slug> --json
a4 explore catalog stack <slug> --json
```

The descriptor is pinned to the very package that `a4 install` will consume.
Treat it as a single contract. It is not a menu to pick and mix from.

A program descriptor can include:

- program and release identities;
- accounts, instructions, events, and types;
- hosted Program Read availability;
- supported SDK targets; and
- the exact install command.

A stack descriptor can include:

- its exact composition identity;
- selected live views and their programs;
- independent live, Program Read, chain, and transaction bindings;
- authentication requirements;
- supported SDK targets; and
- the exact install command.

If an identity or connection detail you need is missing, treat the package as
unavailable for that operation. Don't fall back to “latest,” guess an endpoint,
or combine parts from two descriptor versions.

## Compatibility discovery commands

These commands remain useful for direct surveys and scripts:

```bash
a4 explore --json
a4 explore programs --json
a4 explore stack <ref> --json
a4 explore program <ref> --json
```

Prefer `a4 explore catalog` when starting from intent or filtering by capability
mode. Prefer the explicit `stack` and `program` forms over legacy positional
stack syntax in new automation.

## Curated knowledge

The catalog tells you _what_ exists. The knowledge layer adds context that
people have reviewed: background on each protocol, the role each program plays,
which concepts are covered, and step-by-step recipes. Where your installed CLI
exposes it:

```bash
a4 know search --query "monitor swaps" --json
a4 know protocol <slug> --json
a4 know program <slug> --section surface --json
a4 know recipe <slug> --json
```

Use it to understand _why_ a program fits what you're trying to do. Then go
back to the exact catalog descriptor before installing or connecting. A missing
recipe means the workflow hasn't been documented yet. It doesn't automatically
mean the workflow is impossible.

Knowledge routes may require `a4 auth signup` or `a4 auth login`.

## Install exactly what you inspected

Prefer the descriptor's reported command:

```bash
a4 install program <slug> --ts
a4 install stack <slug> --ts
```

A saved install updates `arete.toml`, resolves `arete.lock`, and generates code
for the complete set of dependencies. Use `--no-save` only when you deliberately
want a one-off output.

## Machine-readable output

Agents and scripts should pass `--json`. The response carries a schema version
and may gain fields over time. Read the fields you need and leave unknown ones
intact. Don't rebuild a response from the examples on this page.

When CLI help and prose differ, current `a4 explore --help`, the JSON response,
and generated types win.
