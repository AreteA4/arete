---
title: Catalog and Descriptors
description: Discover capabilities by intent, then inspect the exact program or stack contract.
---

Arete separates **search** from **exact inspection**:

- the catalog helps an agent find programs and stacks relevant to an intent;
- a descriptor identifies the exact installable package and available delivery;
- generated code supplies the final language-level names and types.

## Search the catalog

```bash
a4 explore catalog --query "monitor swaps" --json
a4 explore catalog --query "manage a multisig" --kind program --json
a4 explore catalog --category defi --mode subscribe --json
a4 explore catalog --kind program --mode read --target typescript --json
```

Available filters:

| Filter                | Meaning                                               |
| --------------------- | ----------------------------------------------------- |
| `--query`             | Free-text intent                                      |
| `--concept`           | Exact catalog concept slug                            |
| `--category`          | Exact category slug                                   |
| `--kind`              | `program` or `stack`                                  |
| `--mode`              | `read`, `build`, or `subscribe`                       |
| `--target`            | Verified `typescript`, `rust`, or `python` SDK output |
| `--limit`, `--cursor` | Bounded pagination                                    |

List canonical concept and category slugs before using exact filters:

```bash
a4 explore catalog --vocabulary --json
```

Catalog contents are live. Do not maintain a hand-written “available stacks”
list in application instructions.

## Inspect an exact result

```bash
a4 explore catalog program <slug> --json
a4 explore catalog stack <slug> --json
```

The descriptor is pinned to the package that `a4 install` will consume. It
should be treated as one contract rather than a bag of suggestions.

A program descriptor can include:

- program and release identities;
- accounts, instructions, events, and types;
- hosted Program Read availability;
- supported SDK targets; and
- the exact install command.

A stack descriptor can include:

- its exact composition identity;
- selected live views and their programs;
- independent live, Program Read, chain, and transaction bindings;
- authentication requirements;
- supported SDK targets; and
- the exact install command.

If a required identity or binding is missing, treat the package as unavailable
for that operation. Do not fall back to “latest,” guess an endpoint, or combine
parts from two descriptor versions.

## Compatibility discovery commands

These commands remain useful for direct surveys and scripts:

```bash
a4 explore --json
a4 explore programs --json
a4 explore stack <ref> --json
a4 explore program <ref> --json
```

Prefer `a4 explore catalog` when starting from intent or filtering by capability
mode. Prefer the explicit `stack` and `program` forms over legacy positional
stack syntax in new automation.

## Curated knowledge

The knowledge layer adds human-reviewed protocol context, program roles,
concept coverage, and recipes. Where exposed by the installed CLI:

```bash
a4 know search --query "monitor swaps" --json
a4 know protocol <slug> --json
a4 know program <slug> --section surface --json
a4 know recipe <slug> --json
```

Use it to understand _why_ a program fits an intent. Return to the exact
catalog descriptor before installing or connecting. A missing recipe means the
workflow is not documented, not automatically that it is impossible.

Knowledge routes may require `a4 auth signup` or `a4 auth login`.

## Install exactly what you inspected

Prefer the descriptor's reported command:

```bash
a4 install program <slug> --ts
a4 install stack <slug> --ts
```

A saved install updates `arete.toml`, resolves `arete.lock`, and generates the
complete dependency graph. Use `--no-save` only for a deliberate one-off output.

## Machine-readable output

Agents and scripts should pass `--json`. The response has a schema version and
may gain fields over time. Read the fields you need and preserve unknown fields
rather than reconstructing a response from examples in this page.

When CLI help and prose differ, current `a4 explore --help`, the JSON response,
and generated types win.
