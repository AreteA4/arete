Most of Arete is open source and you can run it yourself. The hosted service
at `api.arete.run` adds managed services:
discovery, review, verifiable receipts, current program knowledge, and
operations. This page explains what is what.

## What is open source

The SDKs, the CLI and the tooling you install into a project are in the
[AreteA4/arete](https://github.com/AreteA4/arete) repository:

| Component                                               | Licence    |
| ------------------------------------------------------- | ---------- |
| The `a4` CLI, its dev UI and the MCP server (`a4 mcp`)  | Apache-2.0 |
| The stack DSL, the interpreter and the server crates    | Apache-2.0 |
| The hash formats (`arete-hash`)                         | Apache-2.0 |
| The Rust SDK and `arete-idl`                            | MIT        |
| The TypeScript SDK (`@usearete/sdk`) and React bindings | MIT        |
| `@usearete/protocol`: the handler ABI and its runner    | MIT        |
| The Python SDK (`arete-sdk`)                            | MIT        |

Each package's `LICENSE` file is authoritative. Self-hosting the
[open-source stack server](/a4-server/overview/) for your own app is welcome.

## Development: cloud dev environments

[`a4 dev`](/cli/local-development/) develops against an Arete cloud dev
environment: a persistent fork of mainnet that Arete hosts for your account,
where your protocol runs as it will in production, decoded by the same
decoder. The CLI, the MCP server, the dev UI and your keys stay on your
machine: transactions are signed locally, and `a4 dev up` serves the
environment's RPC on `127.0.0.1` for wallets and apps. Environments count
against your plan (environments, active hours, storage, requests).

## What the hosted service adds

| Hosted                    | What you get                                                                                                                                             |
| ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Registry and discovery    | Packages that agents and MCP clients find by intent, with exact versions to install                                                                      |
| Review and receipts       | Reviewed releases, and a signed receipt for each attested execution that anyone can check offline and against the chain (`protocol_receipt` in `a4 mcp`) |
| Current program knowledge | Program specs kept current as programs upgrade                                                                                                           |
| Hosting                   | Live stacks with history, protocol deployments, and SLAs                                                                                                 |
| Cloud dev environments    | Persistent mainnet forks for development, with checkpoints, branches, rebase, scenarios and transaction previews                                         |

## Fees

Protocol fees apply to execution on the hosted service. They pay for
discovery, review and operations, not for the code: running the open-source
components yourself doesn't involve Arete's fee. The hosted service enforces its platform fee policy alongside the protocol's
declared fee policy; a creator cannot disable the platform fee by changing
the protocol document. Applicable fees and creator allocations are included
in the execution summary and attested receipts.

Fee caps and enterprise terms are available on request. See
