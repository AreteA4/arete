# Rust DSL Selection Guide

Read this reference when choosing mappings, population strategies, views, computed fields, or resolvers. Use current compiler diagnostics and Arete docs for exact macro grammar.

## Structure

- `#[arete(idl = [...])]`: generates typed program modules and artifacts.
- `#[entity(name = "...")]`: declares one app-facing entity.
- `#[view(...)]`: adds a selected sorted/filtered projection; state and list views are generated by default.
- Nested sections derive `Stream`, `Debug`, `Clone`, `Serialize`, and `Deserialize` as required by the current DSL.
- Exactly one field route must establish the entity primary key.

## Field Sources

| Attribute | Use when |
| --- | --- |
| `#[map]` | A field comes from decoded account state |
| `#[from_instruction]` | A field comes from an instruction argument or account |
| `#[aggregate]` | Instruction/event updates accumulate a value |
| `#[event]` | The model intentionally retains event records |
| `#[snapshot]` | The model retains a complete account snapshot |
| `#[derive_from]` | A value comes from instruction context such as time/slot |
| `#[computed]` | A value derives purely from other entity fields |
| `#[resolve]` | Data is fetched from an explicitly configured off-chain resolver |

Use generated `program_sdk::accounts`, `instructions`, and type paths. Do not replace a missing generated path with a string.

## Strategies

- `SetOnce`: immutable identity established once.
- `LastWrite`: latest authoritative value.
- `Sum` / `Count`: monotonic aggregates when reversal/reorg semantics are acceptable.
- `Append`: retained sequence with an explicit retention policy.
- `Min` / `Max`: extrema with suitable reset semantics.

Choose based on domain lifecycle, not convenience. Keep raw token values in integer types; use current amount helpers or computed fields for display amounts.

## Cross-Account Resolution

`lookup_by` tells an instruction-derived update which account address to use for routing. The named account must appear on that exact instruction.

`lookup_index(register_from = [...])` registers an address-to-primary-key relationship from proved instruction/account context. It is not a general database join.

## Resolvers

Use resolvers for data that is genuinely off-chain, such as token metadata or a URL-backed document. Model failure and delayed hydration as optional state. Never use a resolver to hide a missing on-chain join or to fetch secrets into streamed entities.

## Compiler Loop

Add one coherent mapping category at a time and run `cargo check`. Read the first macro diagnostic, inspect the generated IDL module when helpful, and correct the model. Do not stack speculative fixes across many macros before recompiling.
