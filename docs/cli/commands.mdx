# CLI Command Reference

Complete reference for the Arete CLI (`a4`).

---

## Global Options

| Option | Description |
|--------|-------------|
| `--config, -c <path>` | Path to arete.toml (default: `arete.toml`) |
| `--json` | Output as JSON |
| `--verbose` | Enable verbose output |
| `--completions <shell>` | Generate shell completions (bash, zsh, fish, powershell, elvish) |
| `--help, -h` | Show help |
| `--version, -V` | Show version |

---

## Quick Reference

| Command | Description |
|---------|-------------|
| `a4 init` | Initialize project |
| `a4 program build <idl>` | Build a portable ProgramSpec |
| `a4 stack compose` | Compose ProgramSpecs and aliased LiveSpecs |
| `a4 up <manifest>` | Deploy one exact StackManifest |
| `a4 status` | Show project overview |
| `a4 auth login` | Authenticate |

---

## Project Setup

### a4 init

Initialize a new Arete project.

```bash
a4 init
```

Creates `arete.toml` and `.arete/`. Rust DSL builds write ProgramSpec,
LiveSpec, and StackManifest artifacts directly.

### a4 config validate

Validate your configuration.

```bash
a4 config validate
```

## Authentication

### a4 auth login

Save an API key for the selected environment.

```bash
a4 auth login
a4 auth login --key <your-api-key>
```

### a4 auth logout

Remove stored credentials.

```bash
a4 auth logout
```

### a4 auth status

Check local authentication status.

```bash
a4 auth status
```

### a4 auth whoami

Verify authentication with server.

```bash
a4 auth whoami
```

**Credentials location:** `~/.arete/credentials.toml`

## Deployment

### a4 up <manifest>

Deploy one exact local StackManifest.

```bash
# Deploy the exact composition
a4 up .arete/MyStack.stack-manifest.json

# Deploy to branch
a4 up .arete/MyStack.stack-manifest.json --branch staging

# Preview deployment
a4 up .arete/MyStack.stack-manifest.json --preview
```

Composite `.stack.json` is an input-only compatibility adapter through **August
31, 2026**. Do not deploy by name for new workflows.

**Options:**

| Flag | Description |
|------|-------------|
| `--branch, -b <name>` | Deploy to named branch |
| `--preview` | Create preview deployment |
| `--dry-run` | Show what would be deployed without deploying |

### a4 status

Show overview of all stacks, builds, and deployments.

```bash
a4 status
a4 status --json
```

## Stack Management

### a4 program build <idl>

```bash
a4 program build ./idl/my-program.json \
  --output ./.arete/my-program.program-spec.json
```

### a4 live build <legacy.stack.json>

Normalize a supported legacy input into a LiveSpec and ProgramSpecs:

```bash
a4 live build ./Legacy.stack.json \
  --output ./.arete/Legacy.live-spec.json \
  --program-dir ./.arete/programs
```

### a4 stack compose

```bash
a4 stack compose --name MyApp \
  --live core=./Core.live-spec.json \
  --live analytics=./Analytics.live-spec.json \
  --artifact-dir . \
  --selected-view core=Position/state \
  --selected-view analytics=Volume/list \
  --output ./MyApp.stack-manifest.json
```

Each alias can receive an independent live binding. Program Read, chain, and
transaction transports remain independent too.

### a4 stack list

List all stacks with deployment status.

```bash
a4 stack list
a4 stack list --json
```

### a4 stack push [stack-name] (legacy)

Push a legacy configured composite input. This compatibility command is retained
only through **August 31, 2026**.

```bash
# Push all stacks
a4 stack push

# Push specific stack
a4 stack push my-stack
```

### a4 stack show <stack-name>

Show detailed stack information including deployment status and recent builds.

```bash
a4 stack show my-stack
a4 stack show my-stack --version 3
```

### a4 stack versions <stack-name>

Show version history.

```bash
a4 stack versions my-stack
a4 stack versions my-stack --limit 10
```

### a4 stack delete <stack-name>

Delete a stack from remote.

```bash
a4 stack delete my-stack
a4 stack delete my-stack --force  # Skip confirmation
```

### a4 stack rollback <stack-name>

Rollback to a previous deployment.

```bash
# Rollback to previous version
a4 stack rollback my-stack

# Rollback to specific version
a4 stack rollback my-stack --to 2

# Rollback to specific build
a4 stack rollback my-stack --build 123

# Rollback branch deployment
a4 stack rollback my-stack --branch staging
```

**Options:**

| Flag | Description |
|------|-------------|
| `--to <version>` | Target version |
| `--build <id>` | Target build ID |
| `--branch <name>` | Branch to rollback |
| `--rebuild, -r` | Force full rebuild |
| `--no-wait, -n` | Don't watch progress |

### a4 stack stop <stack-name>

Stop a running deployment.

```bash
a4 stack stop my-stack
a4 stack stop my-stack --branch staging
```

## Build Commands (Power User)

These commands are for advanced users who need fine-grained control over the build process.

### a4 build create <stack-name>

Create a new build from a stack.

```bash
a4 build create my-stack
a4 build create my-stack --version 2
a4 build create my-stack --ast-file ./my-stack.ast.json
a4 build create my-stack --no-wait
```

**Options:**

| Flag | Description |
|------|-------------|
| `--version, -v <n>` | Use specific version (default: latest) |
| `--ast-file <path>` | Use local AST file directly |
| `--no-wait, -n` | Don't wait for completion |

### a4 build list

List all builds.

```bash
a4 build list
a4 build list --status completed
a4 build list --limit 10
```

### a4 build status <build-id>

Get detailed build status.

```bash
a4 build status 123
a4 build status 123 --watch
a4 build status 123 --json
```

## SDK Generation

### a4 install <stack>

Install a published hosted stack SDK.

```bash
a4 install ore-stack-abc123 --ts
a4 install ore-stack-abc123 --rust
```

### a4 install program <program>

Install a published hosted program SDK.

```bash
a4 install program spl-token --ts
a4 install program system-program --ts
```

### a4 sdk list

List stacks available for SDK generation.

```bash
a4 sdk list
```

### a4 sdk create --manifest <path> --ts|--rust

Generate local SDK source from one exact StackManifest.

```bash
a4 sdk create --manifest .arete/MyStack.stack-manifest.json --ts
a4 sdk create --manifest .arete/MyStack.stack-manifest.json --rust
a4 sdk create --program-spec .arete/my-program.program-spec.json \
  --program-only --ts
```

Generation does not publish packages; a trusted operator publishes reviewed
npm/crates.io output manually.

## Configuration File

**File:** `arete.toml`

```toml
[project]
name = "my-project"

# SDK generation settings
[sdk]
output_dir = "./generated"
typescript_package = "@myorg/my-sdk"

# Build preferences
[build]
watch_by_default = true

# Legacy composite inputs (compatibility only through August 31, 2026)
[[stacks]]
name = "my-game"
stack = ".arete/SettlementGame.stack.json"
description = "Settlement game tracking"
```

## Build Process

### Status Flow

```
pending → uploading → queued → building → pushing → deploying → completed
                                                              ↘ failed
```

### Build Phases

| Phase | Description |
|-------|-------------|
| SUBMITTED | Queued for processing |
| PROVISIONING | Starting build environment |
| DOWNLOAD_SOURCE | Preparing source |
| INSTALL | Installing dependencies |
| PRE_BUILD | Preparing build |
| BUILD | Compiling |
| POST_BUILD | Finalizing |
| UPLOAD_ARTIFACTS | Publishing image |
| FINALIZING | Deploying to runtime |

## Typical Workflows

### First-Time Setup

```bash
# Initialize project
a4 init

# Login with your API key
a4 auth login

# Validate configuration
a4 config validate
```

### Development Cycle

```bash
# Make changes, rebuild Rust crate
cargo build

# Deploy
a4 up .arete/MyStack.stack-manifest.json

# Check status
a4 status
```

### Branch Deploys

```bash
# Deploy feature branch
a4 up .arete/MyStack.stack-manifest.json --branch feature-x

# Check deployment
a4 stack list

# Clean up when done
a4 stack stop my-stack --branch feature-x
```

### Rollback

```bash
# Quick rollback to previous version
a4 stack rollback my-stack

# Rollback to specific version
a4 stack rollback my-stack --to 2
```

## Error Reference

| Error | Solution |
|-------|----------|
| `Not authenticated` | Run `a4 auth login` |
| `Stack not found` | Check `a4 stack list` for available stacks |
| `StackManifest not found` | Run `cargo build` and use the generated manifest path |
| `Build failed` | Check `a4 build status <id>` for details |
| `Config invalid` | Run `a4 config validate` |

## Endpoint and DNS Handoff

Use the deployment record to obtain the assigned bindings:

```bash
a4 stack show <stack-name>
```

Live, Program Read, chain, and transaction endpoints are independent. Operators
map the required bindings through their chosen DNS/CDN provider and manage
records and certificates there; the portable artifacts assume no DNS vendor.
